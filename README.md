# Daily Pentest Challenge

**Start Date:** 24 September 2026

Build consistency in cybersecurity and penetration testing by doing meaningful security work every day. This repository documents the work and acts as proof of progress.

Activities can include:

* Pentesting labs / CTFs
* PortSwigger / TryHackMe
* VM exploitation
* Recon & enumeration
* Networking
* Security books & blogs
* Vulnerability research
* Tool/script development
* Relearning concepts

---

## Challenge Rules

1. Do security-related work every day.
2. Minimum **60 minutes** of focused work.
3. Complete or meaningfully attempt at least **one task**.
4. Document at least **one learning outcome**.
5. Add at least **one piece of proof**.
6. Document failed attempts too.
7. Only test authorized targets.

Focus areas:

* URL/endpoint discovery
* JavaScript analysis
* Parameter discovery
* Scope filtering

Strengthen:

* Routing & NAT
* Subnetting
* IPv4/IPv6

Work through **Penetration Testing: A Hands-On Introduction to Hacking — Georgia Weidman**.

**Read → Understand → Reproduce → Experiment → Document**

### 5. CPENT

Research CPENT requirements, exam structure, domains, practical skills, labs, reporting, and preparation.

Work through vulnerabilities and labs covering areas such as:

# Daily Logs

Each day has its own directory:

```text
├── README.md
├── Day1/
│   └── README.md
├── Day2/
│   └── README.md
└── ...
```

### Daily Log Template

```markdown
# Day X — Date

## Objective
What I planned to accomplish.

## What I Did
- Task 1
- Task 2

## What I Learned
Key concepts and findings.

## Tools Used
- Tool 1
- Tool 2

## Challenges / Mistakes
What failed and why.

## Proof of Concept
Screenshots, commands, code, output, etc.

## Resources
- Labs
- Blogs
- Books
- Documentation

## Metrics
- Time spent: XX minutes
- Practical task: Complete / Attempted
- Learning outcome: <concept>
- Proof: <file/link>
- Status: ✅ / ⚠️ / ❌
```

---

# Proof of Concept

Proof can include:

* Screenshots
* Terminal output
* Burp requests/responses
* Nmap/Wireshark results
* Exploitation steps
* Scripts
* Payloads
* Lab completion
* Notes
* Reports
* Write-ups

A day does **not** require an exploit. Research, networking, development, or a documented failed attempt can also qualify.
